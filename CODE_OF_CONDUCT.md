# MSIM Code of Conduct

## Our Standard

MSIM is a technical project built through respectful, precise, and inclusive collaboration. Participants are expected to:

- Treat people with respect and professionalism.
- Welcome differing viewpoints and technical backgrounds.
- Give feedback that is specific, constructive, and focused on the work.
- Credit ideas, code, and contributions accurately.
- Protect private information, credentials, API keys, logs, and user data.
- Follow the project security policy when reporting vulnerabilities.

Unacceptable behavior includes harassment, discrimination, personal attacks, threats, sexualized conduct, deliberate disruption, publishing private information without consent, and attempts to expose secrets or private user data.

## Project Boundaries

This policy applies to MSIM repositories, issues, pull requests, discussions, and project-related events. The `submodules/anythingllm-mcp` directory is an independently maintained upstream project; its own Code of Conduct and contribution policies apply to activity in that project.

## Reporting

Report conduct concerns privately to the project maintainers. Do not include passwords, API keys, access tokens, private documents, certificates, logs containing sensitive data, or full request bodies. Include the relevant location, a concise description, and any test-only reproduction details that are safe to share.

Security vulnerabilities should be reported according to [SECURITY.md](SECURITY.md), not in a public issue.

## Enforcement

Project maintainers may clarify expectations, remove content, close discussions, restrict participation, or take other appropriate action when this policy is violated. Actions will be proportionate to the behavior and applied consistently.

Retaliation against anyone who raises a good-faith concern is not acceptable.

## Attribution

This policy is adapted from common open-source community standards, including the Contributor Covenant, and is tailored to MSIM's security and upstream-submodule boundaries.
